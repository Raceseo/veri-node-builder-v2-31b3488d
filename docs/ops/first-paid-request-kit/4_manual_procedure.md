# 첫 유료 의뢰 수동 처리 절차 (VeriNode)

첫 유료 설문 1건을 **손으로** 끝까지 굴리는 순서다. 자동화는 없다 — 각 단계에서
Ray가 직접 SQL을 실행하거나 행동한다. SQL 파일은 같은 폴더의 `1_`·`2_`·`3_`.

- 대상 DB: 서울 prod `okeeihfmagfogvuxzszb` (SQL Editor에서 직접 실행)
- 원칙: **draft로 넣고 → 검수 → active**. 검수 전에 절대 active로 열지 않는다.
- 원칙: 결과 파일에는 **응답자 개인식별정보를 넣지 않는다**(익명 순번만).
- 게이트 2개(응답자에게 미리 고지): ①전 문항 응답해야 보상 ②응답시간 합계 30초 이상.

> 소요시간은 문항 12개·목표 100명 기준의 대략치. 실제는 공급자 풀 속도에 좌우된다.

---

## 단계별

### 1. 문의 접수  — *약 즉시~10분*
- **행동**: 의뢰 내용을 한 곳에 적어둔다 — 의뢰인/목적/문항 초안/목표 표본수/희망 마감일/예산.
- 판단: ①학술·마케팅 등 우리가 받는 수요인가 ②문항이 검증 가능한(응답형) 형태인가.
- SQL: 없음.

### 2. 견적 회신  — *약 10~20분*
- **행동**: 가격·표본수·마감일·전달물(집계 요약 + 익명 원본 CSV)을 명시해 회신.
- 이때 **응답자 보상(VN)과 목표 표본수**를 확정한다 → 다음 단계 값이 된다.
- SQL: 없음.

### 3. draft 등록  — *약 15~30분 (문항 작성 포함)*
- **SQL**: `1_survey_insert_template.sql` **[블록 A]**.
  - `title`·`description`·`reward_vn`·`target_responses` 채우고, 문항을 VALUES에 한 줄씩.
  - 유형별 규칙은 파일 상단 주석 참고 (single/multi=options 배열, scale/text=`[]`).
  - **반드시 `status='draft'`** 로 넣는다(템플릿 기본값).

### 4. 검수  — *약 10분*
- **SQL**: `1_survey_insert_template.sql` **[블록 B]** (B-1→B-2→B-3 순).
  - B-1로 `survey_id` 확보(이후 모든 쿼리에 사용), 문항 수 확인.
  - B-2로 순서·유형·options 눈으로 확인.
  - B-3 정합성 점검 3개 값이 **모두 0**인지 확인.
- **행동**: 필요하면 의뢰인에게 문항 미리보기 확인. 수정은 draft 상태에서
  해당 문항 UPDATE 또는 삭제 후 재삽입(아직 응답 0건이라 안전).

### 5. active 전환  — *약 1분*
- **SQL**: `1_survey_insert_template.sql` **[블록 C]** (`status='active'`).
- 이 시점부터 앱 사용자에게 노출된다(RLS). 되돌리려면 같은 파일의 draft 복귀 주석.

### 6. 공급자 모집 글 게시  — *약 10분*
- **행동**: 응답자(공급자)에게 설문 오픈을 알린다 — 인앱 안내/커뮤니티/공지 등.
- 고지 문구에 게이트 2개를 넣는다: "모든 문항 응답 + 성의 있는 참여(너무 빠른 완료는 보상 제외)".
- SQL: 없음.

### 7. 진행률 확인  — *반복 (하루 1~수 회)*
- **SQL**: `2_progress_query.sql` (메인 쿼리, `<SURVEY_ID>` 교체).
  - `유효응답수_검증통과`가 목표에 도달하는지 추적. `응답시작_인원_참고`와 차이가 크면
    (많이 시작했는데 통과가 적으면) 문항 난이도·시간 게이트를 점검.

### 8. 마감 (closed)  — *약 1분*
- **SQL**:
  ```sql
  UPDATE public.surveys SET status='closed', updated_at=now() WHERE id='<SURVEY_ID>';
  ```
- 목표 도달 또는 마감일 도래 시. closed는 사용자에게 다시 비노출(RLS).

### 9. 결과 추출  — *약 10분*
- **SQL**: `3_export_queries.sql`.
  - (a) 원본 매트릭스 → CSV로 저장(SQL Editor의 다운로드/복사).
  - (b-1~b-4) 문항별 집계 → 요약용 데이터.
  - 기본은 **검증 통과자만** 추출됨(유료 상품 기준). 전체가 필요하면 [검증필터] 주석 처리.
- **확인**: 출력에 이름·이메일·원본 user_id가 없는지 재확인(익명 순번 R0001만).

### 10. 요약 전달 (미리보기)  — *약 30~60분*
- **행동**: (b) 집계로 요약본(문항별 분포·척도 평균·주관식 하이라이트)을 만들어 의뢰인에게 전달.
  - **입금 전에는 요약/미리보기까지만.** 익명 원본 CSV 전량은 아직 넘기지 않는다.
- SQL: 없음(9단계 결과 사용).

### 11. 입금 확인  — *의뢰인/은행 처리에 따름*
- **행동**: 실제 입금(계좌)을 확인. **VeriNode 앱의 지갑/잔액과 무관** — 의뢰 대금은 계좌로 받는다.
- SQL: 없음.

### 12. 파일 전달  — *약 5분*
- **행동**: 입금 확인 후 익명 원본 CSV(9-a) + 최종 요약본을 의뢰인에게 전달.
- 전달 후: 이 의뢰의 처리 로그(설문 id, 표본수, 전달일)를 기록으로 남긴다.
